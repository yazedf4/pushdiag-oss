## How to record future evidence

For every credible outside report, record its GitHub issue / PR URL, date, user consent to cite it, what was actually tested, outcome, and limitations. Don't invent issue threads, stars, downloads, or independent testimonials. A personal self-test is valuable for quality, but must be labeled first-party rather than external adoption.

## Funding application guardrail

Codex for Open Source is designed to support maintainers of projects with meaningful use, broad adoption **or** clear ecosystem importance. Being a sole owner of a brand-new repository does not establish those signals. Present the tests and tooling honestly; avoid quoting a 'success probability'.
